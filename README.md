# 影窗 · 夜巡 —— 实时渲染的皮影戏引擎

**WebGL2 shadow-play engine** · 真实阴影贴图 · 镂空透光 · 四幕编排 · 零 SVG · 零位图资源

> ### 🤖 本项目由 **deepseek-v4.1-flash** 完成
> 引擎架构、光照渲染管线、皮影造型与镂空花纹、四幕编排、以及全部自动化验收工具，
> 均由 **deepseek-v4.1-flash** 编写实现。

一个能演戏的皮影戏引擎，附一段 46 秒的完整表演《影窗·夜巡》。

**不是把剪影贴上去。** 幕布后方是一盏真实的透视聚光灯，皮影的每个关节部件都是真实的
遮挡体，被从灯的视角渲染进一张 2048² 阴影贴图；幕布上的剪影是「光被挡住」的结果，
镂空的花纹则是「光穿过孔洞」的结果。

## 光影管线

```
                       灯（SpotLight, 幕布后方 z=-3.2）
                            │
        ①  从灯光视角渲染深度  │   ShadowStage：把每个皮影部件用自写 ShaderMaterial
            map (2048² RT)    │   画进去，alphaTest 不到的像素 discard
                              │   → 镂空孔洞 = 真的透光
                              ▼
        ②  两级可分离模糊       │  只压锯齿；保留真实距离值供幕布直接比较
           (map → blurH → map) │
                              ▼
   ┌──────────────────────────┴───────────────────────────┐
   │  ③ 幕布：自写 ShaderMaterial                          │
   │     · 顶点级褶皱（正弦 + 分形位移，解析法线）           │
   │     · 程序化经纬织纹（颜色图 + 凹凸图）                 │
   │     · 采样深度图做逐像素遮挡判断                        │
   │     · 光锥衰减 + 距离衰减 + 灯芯 POV 透光               │
   │     · 布料扩散：按投射物深度放大采样半径 → 近实远虚      │
   └──────────────────────────┬───────────────────────────┘
                              │  HDR (HalfFloat)
   ┌──────────────────────────┴───────────────────────────┐
   │  ④ 自写后期：亮部提取 → 三级可分离模糊 → ACES →        │
   │     暖调 → 颗粒 → 暗角                                │
   └──────────────────────────────────────────────────────┘
```

几个关键设计：

- **镂空是真透光。** 部件的深度材质里做 `alphaTest`，孔洞处 `discard` —— 阴影贴图里
  孔洞位置仍是「空」，幕布采样到的就是「没被挡住」。所以剪影内部的鳞甲、花窗、刀身花纹
  亮斑是光影计算的结果，不是画上去的亮色。
- **深度编码。** 阴影贴图存「灯光视空间距离」映射到 `[rangeNear, rangeFar]` 的 0–1 值，
  区间按「灯到幕布四角的真实距离 ± 余量」算出。区间必须覆盖真实距离，否则片元被 clamp
  成常量、比对的不是距离而是常数（表现是「影子整片消失」）。
- **近实远虚。** 深度材质把「该投射物离幕布多远」写进 B 通道，幕布按逐样本的这个值放大
  泊松采样半径 —— 实测石头（z=-0.1）边缘过渡 3.00 px、月窗（z=-1.9）4.60 px。
- **全场没有一张位图资源。** 织物、牛皮纸、镂空花纹、人物与道具造型全部由 canvas
  程序化生成（`textures.js` + `shapes.js`，含 13 种传统花纹）。

## 表演：四幕

| 幕 | 时间 | 内容 |
|---|---|---|
| **起 · 上灯 · 入场** | 0 – 11.0s | 灯由一点灯芯渐亮；副将自左侧缓步入场，落步、沉身、停住 |
| **承 · 探看 · 生疑** | 11.0 – 24.0s | 主将入场（8 步，由慢转快），停步、回头两次、抬手搭额远眺，灯焰一暗 |
| **转 · 拔刀 · 激斗** | 24.0 – 37.5s | 抽刀、两记挥刀（一大一小）、旋身甩刀、背身定格亮相 |
| **合 · 收势 · 余韵** | 37.5 – 46.0s | 收刀、退半步、转身走远（步幅衰减），灯缓缓收成一点，最后 2 秒留白 |

编排不是匀速插值，是「预备 → 发力 → 惯性过冲 → 停住」。全部可复现：

- 停顿 **18 处 / 合计 18.84 秒**（独立验证组用另一套阈值自算：14 处 / 17.68 秒）
- 四幕各有实测的「快 — 停 — 慢」
- 全剧峰值 **23 个关节通道同时运动**（@31.5s 旋身），紧接着 0.9 秒定格里
  除刀尖与翎羽的 0.02 rad 微颤外，**所有通道速度严格为 0**
- 步频非均匀 1.20s → 0.50s；左脚抬起时右脚支撑，相位错开

### 重新构建单文件

改动 `src/` 之后：

```bash
node tools/build-single.mjs      # 重新生成 index.html
node tools/export-share.mjs      # 另存一份中文命名的分享副本
```

构建脚本带三道自检，任何一道不过就非零退出：node 解析器验语法、**函数式**模板注入
（见「踩过的坑」第 3 条）、在最终 HTML 上检查 `<script>` 标签配对。

```bash
node tools/repro-user.mjs            # ★ 用不带任何特殊开关的浏览器验证 file:// 直开
node tools/verify-share-file.mjs     # ★ 复制到空目录验证真能独立运行
node tools/gl-feedback.mjs           # ★ 逐阶段读 gl.getError 定位反馈回路
```

`tools/harness.mjs` 是一个**零依赖**的无头 Chrome 驱动：自己写了最小 CDP 客户端
（含 RFC6455 握手）+ PNG 解码器 + 像素统计，所以整条验证链不需要 puppeteer。

`VERIFICATION.md` 是**独立验证组**（未参与实现）的报告：它用 CDP 把模块闭包里的对象
提到 `window` 上做 A/B 实验，逐条对着需求给数字。它在开发过程中抓出了 6 项真实缺陷，
其中最关键的是「shadow map 实际存的是显示颜色而不是深度」—— 它用「把演员贴图刷白、
几何与 alpha 一字不动，剪影从 19 751px 变成 0px」一锤定音，而不是靠读代码猜。

## 踩过的坑

都是真踩过并修掉的，代码注释里也有。写在这里，希望别人少走一遍。

1. **`file://` 下 ES module 会被 CORS 拦掉。**
   `Access to script at 'file:///…/src/main.js' from origin 'null' has been blocked by CORS policy`
   —— 页面会永远停在静态加载文案上，JS 一行都没跑。更坑的是：如果自动化测试带了
   `--allow-file-access-from-files`，这个限制会被**一起绕过去**，于是「测试全绿但用户打不开」。
   所以一定要有一条**不带任何特殊开关**的验证路径（`repro-user.mjs`）。

2. **GPU 对反馈回路的判定比「源 ≠ 目标」更严。** 只要被采样的纹理在**之前某一趟**当过
   渲染目标，就会报 `Feedback loop formed between Framebuffer and active Texture` 并
   **丢弃这次 draw**。这个 bug 完全静默 —— 画面只是泛光变弱。修法：泛光链里放一块
   **专用暂存**目标，它的纹理从头到尾只被采样。

3. **别用字符串做模板替换。** `String.prototype.replace` 会把替换内容里的 `$&` / `$'` /
   `$1` 当特殊模式；three.js 源码里正好有 `'$'` 字面量，`$'` 的含义是「匹配之后的全部内容」，
   于是整个 bundle 被复制一份插进 HTML，凭空多出一个 `</script>`，字符串被劈开 → 白屏。
   用 `replace(marker, () => text)` 这种**函数式替换**。（PowerShell 的 `-replace` 同一个坑。）

4. **手写阴影通道时，`castShadow` / `customDepthMaterial` 都不生效** —— 它们由 three 的
   内建阴影流程读取。必须**手动**换材质、**手动**隐藏非投射体。否则贴图里存的是显示颜色
   （「深度比较」失去意义），地面还会横插在灯与幕布之间压出一条假影。

5. **阴影相机不在场景图里**，three 只在它自己的阴影流程里更新它的矩阵。手写渲染时必须
   每帧 `position.copy(light)` + `lookAt(target)`，否则相机停在原点、什么都拍不到。

6. **FBO 纹理的 v 轴与 NDC 相反**：采样阴影贴图要取 `(u, 1-v)`，否则剪影上下翻转。

7. **全屏四边形的正交相机 `near` 不能是 0**：那会让 `w = -z = 0`、投影退化、整块被裁掉，
   表现是「模糊通道输出全黑」。

8. **泛光的软阈值写错会把纯黑像素也点亮**，一度让整块幕布洗成死白。

9. **`readRenderTargetPixels` 读 Float / HalfFloat 目标时可能返回全 0**（SwiftShader 下实测），
   所以像素级验证全部走 8bit 中间目标，不要相信浮点回读。

10. **模糊通道别只写 `vec3(sum, sum, 0)`** —— 顺手把别的通道擦成 0，会让依赖它的功能
    静默失效（深度柔化就是这样丢的）。

## 已知限制与取舍

老实写明，都有独立验证组的实测数字。

- **灯罩不参与投影。** 想让篾条影只擦到幕布边缘，罩子必须落在阴影相机可见范围内
  （`near ≈ 1.12m`），而那个距离上放大率 ≈ 2.9，投影必然盖满整块幕布（实测覆盖 33.5%
  画面，把演员压没）。拉宽深度区间去容纳它会把 8bit 步进从 0.8cm 恶化到 1.4~2.8cm
  （> `uShadowBias`），人影边缘会抖。**取舍：保剪影清晰。**
  需求里的「暖黄」与「边缘散开」由光照衰减 + 泛光负责，不依赖灯罩。
- **头部部件镂空率偏低**（`head` 约 4.0%；兵器 22.5%、胸甲 16.2%、翎羽 15.8% 达标）。
  屏幕级「剪影内透光面」约 48%，但真正被实体包围的雕刻孔只有约 689 px / 93 个，
  其余透光来自部件之间的缝隙。
- **「光晕在边缘散开」主要靠泛光外溢**：幕布自身的中心/内侧边缘亮度比只有约 1.08×。
- 阴影贴图是 8bit 深度，且只对标记了 `castShadowRaw` 的网格生效；要加更多半透明介质
  需要换浮点深度。
- 泛光是屏幕空间近似，不是体积光；远景柔化靠布料扩散 + 泊松采样，不是物理软阴影（未实现 PCSS）。
- 只在 **SwiftShader 软件光栅**下验证过；真实 GPU 会快很多，但未经真机复测。

## 关于本项目

**作者 / 实现：deepseek-v4.1-flash**

从零写起，没有使用任何现成的皮影素材、没有 SVG、没有位图资源：
材质与花纹是 canvas 程序化生成，光影是真刀真枪的 shadow mapping，
验收是自写的无头浏览器 + 像素级断言，最后再由一个独立的验证流程去挑毛病。

如果你想在自己的项目里用这套管线，看 `src/screen.js`（阴影管线）、
`src/materials.js`（深度材质）与 `src/compositor.js`（后期）这三个文件就够了。
